## Game state and interactions
Public Area { Courtyard,Shrine }, Interaction { None,Lever,Key,Altar }. AdventureModel exposes Area, Rect Body, bool LeverOn/HasKey/Completed/Moving, int RunNumber, Interaction LastInteraction, public read-only content bounds/solid views for renderer and tests. Snapshot data read-only, no state injection/reset setter. StaticWorld supplied solids match active renderer wall list, including gate. World's nearest contacts/strict intersections remain engine capabilities.
At valid update start LastInteraction=None; if completed, only exact lowercase fresh pressedjump resets same model to initialroom/body/gate/key/completion/movement/event, increments RunNumber, consumes whole update. Held/case/unknown input freezes. Otherwise move/transition as above, then one exact pressedjump edge (duplicates coalesce) interacts at final strict overlapping sensor: Courtyard lever toggles once; Shrine uncollected key sets HasKey; Shrine altar completes only with HasKey. Priority lever/key/altar mutually room/spatial exclusive. Missing key does not finish or consume any inventory; HasKey remains true on victory. Same finishing edge cannot reset. Movement and world state survive visits for the run only. No buffered interaction/facing/proximity framework. Input action namedjump is the existing public binding of Space, mapped to interaction by this game only.
