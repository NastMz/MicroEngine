# CF-1 — Create-new checkpoint files

Status: approved2026-10-17 by Codex root after independent checkpoint_design_review PASS. C-003/CAP-013/FR-002/NFR-001/002/004/005; ADR-0007 and CP-1. Only local Windows disk tracer, no full-H3/engine storage support.

## Contract

New public static TurnExplorer.Storage.CheckpointFile.CreateNew(string path, TurnCheckpoint checkpoint) and Read(string path) -> TurnCheckpoint. New net10.0 optional library references TurnExplorer.Model only, no packages/Desktop/native dependencies; existing consumer binaries/models unchanged. Null path -> ArgumentNullException; empty/whitespace path -> ArgumentException, before IO. CreateNew validates checkpoint using existing Encode before any filesystem write, then normalizes path once with Path.GetFullPath. Missing parent is not created; OS path/IO/access failures propagate, no fallback/default save or swallowed errors.

CreateNew writes exactly CP-1 bytes to unique same-directory `.checkpoint-<guid>.tmp` using FileMode.CreateNew/FileShare.None, closes before File.Move(temp,destination,overwrite:false). Never delete/overwrite an existing destination or collision temp. Track temp ownership only after successful creation. Cleanup only owned unpublished temp; after successful move there is nothing left to clean. Preserve a write error if close also fails (AggregateException in write/close order), always attempt close before cleanup. On write/close/move failure attempt owned-temp cleanup; if cleanup also fails throw AggregateException with primary then cleanup, otherwise preserve original exception. Never return success before publication; no crash-durability, hostile-filesystem isolation, concurrent-writer correctness or portable rename atomicity claim. Crash may leave temp files; automatic sweeping not authorized. Callers opt into OS blocking IO outside frame callbacks.

Read opens existing file read-only/FileShare.Read, reads no more than25bytes with short-read loop, then delegates exact-length/schema checks to CP-1. Missing/locked/inaccessible paths propagate OS failures; malformed/truncated/oversized/unsupported content -> FormatException, no file mutation or default session fallback. Returned data/session construction remains independent via CP-1. Caller must choose new filename to save again; replacement not provided.
