## API signatures and validation

LoopOptions(TimeSpan step, int maxUpdates, TimeSpan maxElapsed, int maxPendingInputs=256), immutable properties. Step and maxElapsed strictly positive; maxUpdates/maxPendingInputs positive. No implicit time defaults. InputSnapshot(IEnumerable<string> held, IEnumerable<string> pressed) copies collections; null collections/elements or blank names invalid. bool IsHeld(string action); IReadOnlyList<string> Pressed immutable ordered list, duplicates retained. PlatformFrame(TimeSpan elapsed, InputSnapshot input, bool active=true, bool closeRequested=false) immutable input; null input rejected.

IFramePlatform : IDisposable exposes PlatformFrame Poll(), void Begin(), ICanvas Canvas, void End(). Factory owns partial acquisition until successful return, then H0 owns disposal once. Poll returns monotonic elapsed since prior Poll; first elapsed includes only post-initialization time. Begin commits drawing; factory/adapter cleans partial failed Begin. Canvas valid only between Begin/End, same thread; retained canvas calls outside that window throw InvalidOperationException. Interface implementations must honor these obligations. Engine never disposes Canvas separately.

ICanvas.Clear(Rgba color), Fill(Rect rectangle,Rgba color). Rgba(byte R,byte G,byte B,byte A=255), Rect(float X,float Y,float Width,float Height); Fill rejects nonfinite coordinates/dimensions and negative sizes before native calls (zero allowed). FrameControl.RequestStop() monotonically requests termination, only creating thread. UpdateFrame(TimeSpan Delta,InputSnapshot Input,FrameControl Control); PresentationFrame(double Alpha,TimeSpan DiscardedTime,FrameControl Control), immutable data. Control can be retained only to request same-thread stop; no cross-thread cancellation promised.

FrameLoop.Run(Func<IFramePlatform> createPlatform,LoopOptions options,Action<UpdateFrame> update,Action<ICanvas,PresentationFrame> draw) returns existing Hosting.ExecutionReport. Null arguments rejected before acquisition. Each call creates one H0 session; factory/null/duplicate acquisition and disposal failures follow H0. Loop/Desktop-origin invalid active use throws FrameApiException after cleanup, not ordinary Failed. FrameLoop recognizes this public exception type (including nested draw/End aggregates); if other failures coexist throw AggregateException retaining all primary/cleanup causes. FrameApiException is sealed with an internal constructor in Loop; Desktop is the sole production friend assembly allowed to construct it. No public constructor/factory and no subclassing. Ordinary consumer exceptions cannot create that marker through supported public APIs; reflection/assembly spoofing are outside this API contract. Ordinary consumer exceptions are Failed. Preflight invalid options/input constructors throw argument exceptions. Native/supplied platform failure and callback errors return Failed. Thread affinity extends H0: all callbacks on caller thread; Desktop requires caller use on application entry thread as a documented native precondition, not a falsely claimed runtime detection. The adapter verifies creating-thread affinity and one active adapter window per process.

## Exact frame semantics

1. Check requested stop before Poll. Poll once; close flag stops before update/begin. Negative elapsed fails execution, even inactive. No later non-cleanup callback after stop.
2. Inactive: clear accumulator and pending edges, ignore incoming input; continue presentation with alpha0/discarded0 (not a simulation tick). Resume active uses only new Poll interval; Desktop rebases elapsed to zero on focus transitions, avoiding unfocused time burst. Both pending input cancellation and discarded inactive simulation time are explicit policy, not overload loss.
3. Active: append ordered Pressed edges, fail on maxPendingInputs overflow (never unbounded/silent loss); latest held snapshot applies to all catch-up ticks. Clamp elapsed to MaxElapsed, record excess. Accumulator starts0 in integer TimeSpan ticks. Each completed update receives Step, pending edges only on first update, held state each update. Zero updates retain edges. Stop during update prevents later update/presentation.
4. At most MaxUpdates completed updates per frame. Drop remaining whole-step backlog, retain fractional remainder; DiscardedTime for this presentation sums elapsed clamp and dropped whole steps. Alpha=remainder/Step in [0,1). Checked arithmetic overflow is a Failed execution, not wrapped or silent time loss. No cross-platform floating-point/physics determinism guarantee.
5. Begin then draw then End exactly once after successful Begin, even draw failure/stop. Failed Begin has no host End. If draw and End both fail, PrimaryError is AggregateException with draw then End in InnerExceptions; platform disposal errors remain H0 CleanupErrors. Single draw/End failure remains primary directly. Stop during draw still End then teardown. No H0 public report growth.

## Desktop and consumer limits

DesktopWindowOptions(int width,int height,string title), positive dimensions/nonblank title. DesktopPlatform(options) initializes one Windows window, validates readiness, cleans partial initialization, maps Left/A -> left, Right/D -> right, Space -> jump, Escape/window close -> close. It disables held/edges when unfocused and ignores minimized time; resize/high-DPI scaling excluded by nonresizable fixed logical canvas640x360 default consumer, not a general display contract. Poll uses Stopwatch, focus transitions rebase. Native clear/begin/end thread-bound, disposal idempotent same thread. A CAS reservation is taken after constructor validation and before native initialization; conflict throws FrameApiException without native calls. Initialization failure attempts Close then releases reservation only if cleanup succeeds; uncertain cleanup poisons reservation until process exit. Same rule applies to disposal. Wrong-thread calls throw before touching native state, including after disposal. Begin commits only on successful return; End clears active drawing before native call so it is attempted at most once. Dispose with active drawing attempts End then Close, retaining both errors; disposed is set before calls, retry is forbidden. Native operation failure is ordinary execution failure, invalid disposed/lifetime/thread use FrameApiException. An internal IDesktopApi injection seam plus internal constructor is visible only to checks/Desktop.Contracts (friend assembly Desktop.Contracts); no public backend-injection API. Deterministic seam tests cover readiness/init failure, cleanup failure/poison in isolated process where needed, reservation conflict/release, wrong-thread/disposal, Canvas lifetime and focus/minimize rebasing. No background native loop or native types exported.

Consumer owns x/y/velocity/grounded and gravity/jump/floor. Uses step1/60s, max5updates, maxElapsed250ms, input bound256. Movement180units/s, jump300units/s, gravity900units/s²; floorY300, player24x32, x clamped0..616. Grounded jump only on pressed jump, no held repetition or airborne jump; floor clamp zeroes vertical velocity. No engine collision module. Pure game model public for tests, no internal engine access. Default interactive; --smoke N runs N presented frames and auto-stops, bounded1..600; --fail-update forces ordinary update failure for native teardown evidence. Unknown/invalid args exit2 with usage; completed/Stopped exit0, Failed exit1. Console reports outcome and frames, no fake game acceptance. Native smoke output is evidence, not playability proof.

## Exact managed public surface (H1-R1)

- InputSnapshot constructor above; IsHeld(string action) rejects null/blank via ArgumentException, ordinal case-sensitive names; Pressed:IReadOnlyList<string>, Held:IReadOnlySet<string> backed by immutable copies.
- PlatformFrame readonly record struct(TimeSpan Elapsed, InputSnapshot Input, bool Active=true, bool CloseRequested=false); default struct/null Input is invalid platform result, Failed after cleanup.
- Rgba readonly record struct(byte R,byte G,byte B,byte A=255); Rect readonly record struct(float X,float Y,float Width,float Height).

- UpdateFrame internal constructor; getters Delta:TimeSpan, Input:InputSnapshot, Control:FrameControl.
- PresentationFrame internal constructor; getters Alpha:double, DiscardedTime:TimeSpan, Control:FrameControl.
- FrameLoop static class with public static Hosting.ExecutionReport Run(Func<IFramePlatform>,LoopOptions,Action<UpdateFrame>,Action<ICanvas,PresentationFrame>).

## Cross-cutting architecture clarification — ADR-0004

[ADR-0004](../decisions/0004-replaceable-infrastructure.md) constrains future evolution without changing H1-R1 signatures/behavior/acceptance. IFramePlatform/ICanvas and the Run factory are the public custom-provider seam; IDesktopApi is only the concrete adapter's private test seam. No custom provider needs Desktop, Raylib or friend access to run a conforming primitive graphical profile. Ordinary custom-provider exceptions remain execution failures under current rules; equivalent privileged engine-origin API-error classification is NOT promised.

This synchronous input/time/primitive-canvas combination is an opt-in H1 profile, not the universal platform interface. Headless and future nonmatching capabilities must not be forced through it. Desktop's native entry-thread/single-window/key mapping restrictions stay adapter-specific. Future browser scheduling may require a different driver; no browser support or driver is added now. Optional features require demonstrated contracts, not new mandatory methods here.

Known implementation coupling: Loop's Desktop friend-name privilege for internal FrameApiException. This is not the extension protocol and must not be copied for future providers. F-011 records the limitation and review trigger: changes to this boundary must design backend-independent origin/guard handling before broadening provider claims. No source change or claim of resolved coupling in this documentary clarification.
