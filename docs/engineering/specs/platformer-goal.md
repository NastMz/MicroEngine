Other consumers/default tests remain goal-disabled.

Update validates input null then positive delta before any state changes. If Completed: held/unknown/case/other input has no effect; first exact lowercase pressedjump (duplicates coalesce) resets X40,Y268,VerticalVelocity0,Groundedtrue,Completedfalse and clears all pending jump intent, then consumes the entire update. No held movement/jump is integrated during reset; next valid update resumes existing rules. No new action vocabulary. Reset reuses controller/options/immutable obstacles, so existing focus/close buffer cancellation remains valid; no exposed general Reset API or new mutable controller instance.

Otherwise execute unchanged movement/jump/buffer/contact logic. After contact/buffer processing, only if GoalEnabled, Grounded, Y==268 and body24x32 strictly overlaps Goal, set Completedtrue, verticalvelocity0 and clear buffer. Edge touch at X+24==580 or airborne pass does not complete; no continuous swept-goal test. A buffered landing that immediately launches remains airborne and cannot complete that update. Completion latches until a fresh reset; the same jump edge that reaches the goal cannot also reset. GoalEnabledfalse never completes/freezes, including at the right boundary. Every positive TimeSpan retains existing finite behavior; no new performance promise.
