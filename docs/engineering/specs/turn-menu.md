# TM-1 — External exploration/menu/turn tracer

Status approved2026-10-17 by Codex root under delegation after turn_menu_design_review targeted recheck PASS; ME-028 completed, ME-029 ready. Owner continuation2026-10-17, H3/C-003/FR-002, ADR-0004. This is a narrow menu/turn-flow probe, not full H3/Pokemon or engine UI/combat/persistence support.

## Outcome and alternatives

A new TurnExplorer consumer reuses the two-room exploration model, opens a two-option menu at the marker, resolves one turn per fresh confirmation and returns to exploration. Existing examples and all149tests remain unchanged. The game owns every menu/turn rule. No battle system, stats/resource economy, RNG, NPC/dialogue, inventory/progression/save, assets, UI toolkit, entity/world architecture, text rendering or new backend/key mappings.

Prefer a procedural two-row menu with console labels as the smallest first flow test through existing ICanvas. Do not widen ICanvas or introduce optional ITextCanvas before the consumer demonstrates a need for in-window labels. That remains a documented usability limitation/candidate, not a claim that colors replace a production menu. Reject modifying RoomExplorer's existing game rules; compose its model in a distinct consumer. No significant engine architecture change/new ADR required.

## Exact consumer model/dependencies

New examples/TurnExplorer.Model net10.0 references RoomExplorer.Model and Loop only; no Desktop/native/FirstPlayable. New namespace TurnExplorer.Model; public enum MenuOption { Advance, Return }; public sealed TurnSession privately owns a new Explorer. Expose get-only Room Room,float X,Y,bool MarkerActivated forwarding that instance; bool MenuOpen (initialfalse), MenuOption SelectedOption(initialAdvance), int TurnPhase(initial0), bool TurnResolved(initialfalse), private mutation. Do not expose the mutable Explorer instance. Reuse Explorer's public marker content constants at the presentation boundary; no duplicated level geometry or engine type leaks.

public void Update(TimeSpan delta,InputSnapshot input): input-null first, then delta>0 ArgumentOutOfRangeException(nameof(delta)); invalid calls preserve all state, including a prior TurnResolvedtrue. No wall-clock/global mutable state.

- Each valid update clears TurnResolved.
- When menu closed: update the owned Explorer exactly once using original delta/input. If its InteractionOccurred is true, open menu and reset SelectedOption=Advance. Consume that update entirely: the opening Space/jump edge never resolves a turn, even with duplicate edges. Otherwise normal exploration; turn phase unchanged. Movement/portals retain RE-1/IM-1 semantics.
- When menu open: do not update Explorer (position/room/marker remain frozen regardless of held movement); process input.Pressed in its recorded order. Exact lowercase up or down each toggles the two-option selection (including duplicate navigation edges, each is one event). Held actions alone, left/right, unknown/case-mismatched edges do nothing. Do not add a global confirm/cancel input vocabulary.
- First exact jump edge confirms current selection and ends processing this Update; ignore all later edges. If Advance: TurnPhase=(TurnPhase+1)%4, TurnResolved=true, menu remains open. If Return: close menu, TurnResolvedfalse, phase retained, movement does not resume in that update. Thus [down,jump] returns without a turn; [jump,down] advances and leaves selectionAdvance. Duplicate confirmations resolve at most one turn. A later fresh confirmation may resolve another; held Space never repeats.
- Next update after Return resumes exploration without a latent edge; next marker interaction reopens with Advance selected. The four-position cyclic phase is a bounded visible turn indicator, not combat/progression or an unbounded event counter. State is instance-local/in-memory, fresh session resets.

## Executable and presentation

New examples/TurnExplorer net10.0 references TurnExplorer.Model, RoomExplorer.Model for immutable content/enums, and Desktop. Uses existing public FrameLoop (1/60step,5maxupdates,250msmaxelapsed),640x360window, existing room/passage/marker/player geometry/colors. No changes to engine or previous model/source projects. While menu open the world is visible but frozen.

Draw phase pips always, whether menu is open or closed. Draw four turn pips at(20+20*i,20,12,12), i0..3; current phase cyan(70,200,210), others gray(70,75,85). Draw menu overlay rows and their option glyphs only while MenuOpen is true; they are absent initially and immediately after Return. Draw overlay rows at(420,40,200,40) and(420,88,200,40), selected gold(240,180,65), other gray(70,75,85). Inside top row draw one dark(24,28,40)12x12square at(432,54); inside bottom row two at(432,102) and(452,102). One-square top option=Advance, two-square bottom=Return. No text/texture capability claimed. Player/world render order unchanged; overlay/pips drawn last, renderer never updates state. Put only these pips/menu operations in internal TurnExplorer.MenuRenderer.Draw(ICanvas canvas,TurnSession session), validating null canvas then session before any draw. Program calls it after world rendering; source-link this actual file into Loop.Contracts without Desktop linkage. Presentation tests record Fill calls:4pips closed,9calls open (4pips,2rows,3glyphs), then4pips after Return; compare authored coordinates/colors/selection/phase and repeated-render state purity.

Console controls explain Arrows/WASD exploration, Space at marker opens menu, up/down then Space navigates/confirms; top=Advance, bottom=Return; Escape/window close exits. After each fixed model update print state changes only: room:<Room> on room change; menu:open;selected:Advance when opened; menu:selected:<MenuOption> when open selection changed without closing; turn:phase:<0..3> once when TurnResolved; menu:closed on return. Order room, menu(open/selection/closed), turn. No original IM-1 interaction trace required in this distinct executable. No repeated trace from rendering/held keys.

CLI preserves bounded --smoke N(1..600), --fail-update and usage/outcome/error conventions of earlier consumers, with Usage: TurnExplorer. No args interactive; normal/failure/usage exits0/1/2. New checks/TurnExplorerSmoke.ps1 follows current timeout/process-isolation harness and tests native60presentations+updates/close, requested callback failure/close and five invalid CLI cases. This is startup/CLI/lifecycle evidence, not physical menu-key automation or subjective usability.
