## Fixed spatial content

New public consumer model in MapExplorer.Model, references only Loop. `enum Zone { Meadow, Ruins }`; readonly record struct `Landmark(Rect Bounds,Rgba Color)`; sealed `MapLayout` with get-only Width/Height/Background/Landmarks and static `For(Zone)` returning fixed immutable definitions, rejecting unknown zone with ArgumentOutOfRangeException. No public mutable collection/construction/loader or universal map format. Meadow1280x720, background24/40/32; Ruins960x540, background32/24/48. Meadow landmarks (200,80,100,60),(400,240,100,80),(900,500,120,80), colors respectively95/130/165,180/100/70,80/150/90; Ruins landmarks(160,100,100,100),(700,360,120,80), colors95/130/165 and180/100/70. Landmarks are decorative/nonblocking, never implied solids.

`MapWalker`: get-only Zone, X,Y; initial Meadow40,304, body24x32. `Create(Zone,float x,float y)` validates defined zone then finite coordinates within current room [0,width-24] and [0,height-32], rejecting with ArgumentOutOfRangeException before creation. Get-only `CameraX`,`CameraY` derived from player center minus half640x360 viewport, clamped0..(mapDimension-viewportDimension); no camera easing/interpolation/state, zoom or engine ICamera.

`Update(TimeSpan delta,InputSnapshot input)` validates input null then delta>0 before mutation; all positive deltas including MaxValue supported. Held right-left/down-up normalized on diagonals, speed180units/sec, opposite directions cancel; pressed-only/unrelated/jump ignored. Compute requestedX from oldX; clamp Y first to0..height-32. At current room's passage, full body resolvedY>=240 and resolvedY+32<=400 required. Meadow requestedX>width-24 ->Ruins8,304; Ruins requestedX<0 ->Meadow1248,304. Boundary alone never transitions; return immediately discards all remaining motion, at most one transition/update; no stationary retrigger. Otherwise clamp X0..width-24, commit resolvedY. Same end-of-update portal eligibility as RE-1, not a swept-motion promise. Changing rooms immediately recomputes camera against destination dimensions; no map loading/resource lifecycle. Separate instances/replay deterministic.

## Presentation and executable

New internal MapRenderer.Draw(ICanvas,MapWalker): null canvas then game checks, no model mutation. Clear current background. Draw landmarks in authored order, cyan70/200/210 passage rectangle (width-8,240,8,160) for Meadow or(0,240,8,160) for Ruins, then gold240/180/65 player. Subtract camera from all world positions and intersect each rectangle with [0,640]x[0,360]; skip empty results. No native scissor, mandatory image/label profile or engine transform. Pure primitive provider remains valid. Larger world and translation must be actual observable native pixels, not only console claims.

MapExplorer exe references model and Desktop only. Window640x360, FrameLoop step1/60sec,maxupdates5,maxelapsed250ms. Controls arrows/WASD move; cyan edge passage changes map; Escape/window close exits; no interaction/combat/persistence. No args interactive. `--smoke N(1..600)` optional once and `--fail-update` optional once, order-independent; anything invalid prints `Usage: MapExplorer [--smoke N(1..600)] [--fail-update]`, exit2 before native acquisition. Callback requested failure ApplicationException("Requested update failure.") before mutation; stopped exit0, reportFailed exit1, preserve outcome/frames/updates/primary/cleanup trace conventions. Print `zone:Ruins`/`zone:Meadow` only on actual transitions. Initial controls explicitly say large map scrolls and cyan portal is at right edge in Meadow/left edge in Ruins. Do not claim native physical-key automation from scripted state rendering.
