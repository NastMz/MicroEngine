# RE-1 — Two-room external exploration tracer

Status approved2026-10-16 by Codex root under delegation after explorer_design_review targeted recheck PASS; ME-022/023/024 completed, technically verified. Owner continuation2026-10-16, roadmap H2/FR-002/ADR-0004. This is not full H2 or a reusable engine scene/world contract.

## Decision and exclusions

Validate a second independent movement/transition model through the same public Loop/Desktop primitives. Use exactly two source-authored rooms and a visible edge passage; no combat, inventory, progression, NPCs, persistence, texture assets, ECS, scene manager, camera, tile/level format, internal obstacle system or backend change beyond additive digital mappings. Existing H1 consumer/model behavior remains unchanged; Desktop mapping is additive, and all117baseline tests remain retained and passing. The full H1 subjective milestone remains unaccepted; this independent architectural probe does not require inventing additional H1 work or inferring acceptance.

Alternative: extract reusable scenes/maps/assets now; defer without concrete ownership/transition demands. Alternative: reuse platformer model/project; reject because top-down rules must be independent of gravity/jump/solid policies. Existing public InputSnapshot/FrameLoop/ICanvas suffice. Missing native up/down mappings are an explicit bounded adapter delta, not new engine action semantics.

## Model and exact update

New examples/RoomExplorer.Model project net10.0, references only engine/Loop. New public enum Room { Courtyard, Hall }; public sealed Explorer with get-only public Room Room, float X,Y (private mutation). Initial Courtyard,X40,Y164. Body24x32, world640x360, logical boundsX0..616,Y0..328. Source-authored two-room topology only; no room/config API, dependencies or gameplay inheritance.

public void Update(TimeSpan delta,InputSnapshot input): validate input null first, then delta>0 with ArgumentOutOfRangeException(nameof(delta)); no mutation on invalid call. Held right-left and down-up yield each axis-1/0/1; opposite keys cancel, unrelated/jump/Pressed actions ignored. Speed180units/sec; when both axes nonzero divide each by MathF.Sqrt(2) before integration so diagonal speed is not faster. Use float seconds=(float)delta.TotalSeconds, clamp requested Y first; requested X computed from oldX. Every positive TimeSpan including MaxValue allowed, finite float arithmetic for current bounded coordinates/speed.

- Courtyard has a right-edge passage; Hall a left-edge passage. Trigger only if requestedX>616 in Courtyard, or requestedX<0 in Hall, and resolved Y>=120 and Y+32<=240 (full body inside inclusive opening). Exact X boundary alone does not transition; movement must attempt beyond it. Otherwise clamp X to0..616; all other edges stop movement.
- East transition sets Hall,X8,Y164; west sets Courtyard,X608,Y164. A transition discards remaining displacement including Y, occurs at most once per update, and consumes no button edge. Spawn does not retrigger without subsequent directional motion across the passage. Large delta never traverses multiple rooms. Pressed-only actions never move or transition. No wall-clock/render mutation; deterministic state-only updates. No promise of swept portal trajectory: eligibility is evaluated at the clamped end-of-update Y, not continuous diagonal time of impact.

## Desktop mapping prerequisite

Add "up" mapped to Up/W and "down" to Down/S in Desktop, retaining left/Left+A, right/Right+D, jump/Space exactly. Implement internal DesktopActions.Read(Func<KeyboardKey,bool> held,Func<KeyboardKey,bool> pressed) returning (string[] Held,string[] Pressed), using the existing Raylib package only inside Desktop. Evaluate each distinct physical key at most once per query kind per poll (Space alias queried once). Digital action once if either alias true. Stable output order left,right,jump,up,down; aliases held/pressed coalesce, sets remain case-sensitive. Native RaylibApi delegates key queries to this pure internal seam; no polling/lifecycle/focus/timing changes. Test all five actions and legacy action outputs; no public binding/config/device contract added. Unknown keys produce no action.
