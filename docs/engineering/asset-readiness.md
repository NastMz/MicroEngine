# Asset Readiness — lightweight content gate
Permanent owner directive2026-10-21. Apply before implementing any visual/sonic content increment.
Use a short section in the existing task/spec, not a new document per asset or a universal ceremony.

1. Name the content's gameplay/feedback function and inventory existing compatible resources.
2. Identify actual gaps; select only required missing resources, or state no gap/N/A.
3. Record publisher/source URL, individual license/conditions, selected file roles, format,
   dimensions/frame regions or audio channels/rate/duration where applicable. Original hashes
   and upstream license/provenance accompany imported third-party files. Preserve originals;
   document conversions and derivative hashes separately. A pack's existence is not clearance.
4. Check interpretation and consumption limits (packed/gutter, animation order, pivots/scaling,
   optional backend support, decode limits; audio format/loop/seams/levels where applicable).
5. Verify use in context: compound tiles/corners and actor/collider readability, draw order,
   animation timing; sound/event association, gain/mix/clipping/loop behavior if audio exists.
   Automated load/hash/pixel/waveform proof is technical evidence, not aesthetic acceptance.
6. Record ready / gap / not-applicable and concrete evidence before dependent construction.

No external content needed: a justified N/A is sufficient. Reused content: reference prior
provenance and verify relevant changed composition; do not re-research unchanged licenses.
Future audio candidates may be evaluated without importing them or implying audio APIs exist.
No routine human approval for public free assets with verified compatible terms. Subjective
coherence/feel is evaluated only at meaningful new playable delivery. Technical gaps become
bounded requirements/ADRs when general infrastructure is justified, never hidden game workarounds.
