# H3.0 — Menu and turn-flow tracer

This bounded consumer scenario is governed by [TM-1](../specs/turn-menu.md), not a full Pokemon game or engine UI/combat/save capability. Specification review precedes construction; see [backlog](../backlog.md) ME-028/029 for actual state and evidence.

## Intended interaction after technical delivery

~~~powershell
dotnet run --project C:\Proyectos\MicroEngine\examples\TurnExplorer\TurnExplorer.csproj -c Release
~~~

Arrows/WASD explore the existing two rooms. At the Courtyard marker press Space to open the menu. While open, movement pauses; up/down changes the highlighted row and Space confirms. The top row (one small square) advances the cyclic four-position turn indicator; the bottom row (two squares) returns to exploration. Console labels name Advance/Return and trace menu/turn changes. Escape/window close exits. This is procedural menu content, not in-window text or a production UI.

## Evidence boundary

Before technical completion the agent must prove model/menu ordering, one confirmation per update, held-key rejection, phase wrap, pause/resume/return/reopen, invalid-call atomicity, deterministic playback, baseline exploration and all149existing tests. Existing/native-new lifecycle/CLI harnesses and independent scratch verification required. Do not infer proof or runnable delivery from this planned packet.

Only subjective menu discoverability, selection clarity and turn response require experience. Do not ask the owner to repeat automated model/CLI/cleanup checks. Console labels are an explicit limitation; feedback may justify a later optional text capability, not automatic widening of ICanvas. Positive owner feedback on the delivered verified increment enables normal main integration under autonomy; full H3 acceptance remains separate.
