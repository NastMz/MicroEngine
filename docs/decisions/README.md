| [0055](0055-animation-tracks-and-timelines.md) | Animation beyond sprite clips as keyframe tracks (`Track<T>`) and timelines with named events (`Timeline`); layers, cross-fades and rigs by composition; skeletal runtimes and state machines stay out of the engine | Accepted |
| [0056](0056-navigation-optional-package.md) | Navigation as an optional `MicroEngine.Navigation` package of the engine's own managed code: A* over grids and graphs, distance fields; navmeshes, generated platformer links and crowds wait (amends 0019) | Accepted |
| [0057](0057-materials-on-the-2d-batcher.md) | Developer-authored rendering is render targets, blend states and materials on the 2D batcher (`Material2D`: the game's shaders with parameters and textures); light, masks, water and post-processing are examples, never engine effects; no new dependency, the device contract unchanged | Accepted |
| [0058](0058-spatial-index-beside-the-world.md) | Nearby objects through an opt-in `SpatialIndex2D<T>` beside the scene world (no region or chunk system); the tile broad phase on the same structure; the world releases and copies in proportion to the work | Accepted |
| [0059](0059-no-first-party-ecs.md) | No first-party Entity Component System for now (deferred and provisional: speed, memory and integration were evaluated, modelling was not; with the conditions that reopen it): the scene world stays the only entity model of the SDK, and a game that needs a component store runs a third-party one beside it through the scene's hooks; no engine assembly may reference one | Superseded by 0065 |
| [0060](0060-scene-systems-and-module-lifecycle.md) | Scene systems (a part of a scene that the engine starts, steps, hashes and stops with it) and module lifecycle hooks (started, stopping, state-hash sections, a system for every scene); the scene's built-in coroutines, tweens, world and widgets keep their fixed place | Accepted |
| [0061](0061-state-machine-in-the-core.md) | A gameplay state machine in the core (`StateMachine<TState, TEvent>`: entries and exits, ways out by condition, time and event, substates, the time in the state, the state hash, snapshots); event workflows use a library such as Stateless directly, with no adapter package | Accepted |
| [0062](0062-one-control-representation.md) | A binding is one list of `InputControl` (keys, chords, gamepad buttons and axes, either stick, mouse buttons, the wheel as an impulse, pointer motion as a value), used by binding, listening and the saved format (version 2, still reading version 1); the pointer's edges and motion; the cursor as an optional platform capability; gestures are not controls |
| [0063](0063-versioned-saves-and-the-games-store.md) | Versioned saves: a `SaveSchema<T>` with one registered step per earlier version, the version as a property of the saved object (`"@version"`; none means 1), a typed load result, every save reading the slot as a load would (newer saves refused and never replaced, with or without a schema; the original of an older save copied, never over an existing copy); storages list their slots; settings are a slot; `Game.Saves` is the game's store on the composition's medium | Accepted |
| [0064](0064-drawing-api-over-the-device-layer.md) | The drawing API is a view of the device layer: a `Texture` exposes its device texture and a render target is one; `IRenderer` draws with states (blend, sampler, material) and into targets; a material is a fragment shader with parameters checked by name (`.shader` version 2) and a declared fallback where shaders cannot run; shaders, materials and render targets are assets. Amends 0057 | Accepted |
| [0065](0065-optional-ecs-package.md) | An optional Entity Component System package, `MicroEngine.Ecs`, over the Arch library (its types are public: the package adopts it and owns the integration: lifetime with the scene, ordered systems, deferred changes, links to scene entities, interpolation, the state hash, registration); the scene world stays the default model; supersedes 0059 | Accepted |
| [0066](0066-content-production-as-data-and-optional-tools.md) | Content production: sheets and animations are data (a `.sheet` description, Aseprite files through the optional `MicroEngine.Aseprite` package over AsepriteDotNet); names, validation and packing are optional `microengine content` steps whose output is ordinary files; `Preload` takes every kind through staged loaders. No content build, no engine format; reload, platform variants and compressed textures are deferred with their designs | Accepted |
| [0067](0067-mix-graph-and-effects.md) | A bus is a submix only while it has effects, is listened to or fades (a mix without effects renders the same bits); effects are a public class fed through the command queue; built-in filters, compressor with sidechain, reverb, delay and a limiter after master; ramps and crossfade (amends 0033) | Accepted |
| [0068](0068-physics-contract-version-2.md) | The physics contract is version 2: character controllers over `Move`, a physics world owned by its scene (`ScenePhysics`, `Game.PhysicsBackend`), dynamics control and joints as defaulted contract members that Box2D implements (native layer version 3); tiles stay the default backend | Accepted |
| [0069](0069-navigation-agents.md) | Navigation moves agents: `NavAgents` (a scene system) follows routes, arrives, searches again when the grid closes the way and keeps bodies apart by steering rules; size takes part in the search; `NavRegions` answers what can be reached; searches are budgeted per step (amends 0056) | Accepted |
| [0070](0070-localization-in-the-core.md) | Localization in the core: string tables as content files (`*.strings.json`, `*.strings.csv`), messages in the ICU MessageFormat syntax formatted by the engine with plural rules keyed by the language tag (no culture data), a `Localizer` in the kernel and `Game.Localization` over the content source, widgets holding a `LocalizedText`, prompt names from the tables, a variant of a file per language, and the tables read by `microengine content check` | Accepted |
| [0071](0071-post-processing-window-stage-mip-levels-draw-order.md) | Post-processing is a chain made of the drawing API (`PostProcess`), on a scene, the canvas or the window, with ready effects that state what they draw where no shader runs; the window stage is a platform capability; mip levels are a texture filter on the devices that have them; draw order is a renderer that sorts (`SortedRenderer`); amends 0057 | Accepted |
| [0072](0072-audio-time-formats-and-spatial-sound.md) | A sound has a position, a heard position, a seek and a loop region, all on the mixer's timeline; one static list of decoders (WAV, OGG, MP3 through NLayer) for effects, music and assets, with seeks made exact by decoding; sounds are released by name or with their asset scope; a scene's listener and emitters are a scene system (`Scene.Sounds`), outside the state hash |
| [0073](0073-saves-of-a-run-nobody-plays.md) | A run nobody plays (a script, deterministic time, a game stepped by a test) keeps its saves in a store of its own, in memory and empty at start (`MemorySaveStorage`); `--saves DIR` and `RunOptions.Saves` name a medium for any run; the composition's medium and a hand-built store are respected; a browser page keeps its storage; saved bindings cannot empty a map; amends 0063 and 0038 | Accepted |
| [0074](0074-time-a-game-can-adopt.md) | Time a game can adopt: a tween is a handle a coroutine yields, holds its starting value from the moment it is added and counts like the hand-written loop it replaces, and a scene advances tweens before coroutines; `Timers` is a kernel class a plain object owns, of which `Scene.Timers` is the scene's; times in seconds on timers and machines are counted in double precision with a tolerance that grows with the time, so `seconds x R` updates is a rule; every time can also be given in updates; a machine's time in a state can be set; `IWorld.Children<T>` walks a group's attachments | Accepted |
| [0075](0075-character-feel-in-one-motion.md) | A character's feel is one `CharacterMotion` (a run, the air's own numbers, momentum, a landing reach, a jump cut by speed, down and jump, the order of carry and jump), bit-identical to before at its defaults; what is the game's own goes through a cuttable `Launch`, `StandOn` and `Snapshot`/`Restore`; a move says what stopped it; a character's origin is the game's choice; tiles per kind of mover are views of one grid; extends 0068 | Accepted |
| [0076](0076-text-effects-and-frame-data-without-game-code.md) | Interpolated text and spans on fonts, one-shot sprite effects, clip frame offsets, points and boxes on sheet frames | Accepted |
| [0077](0077-interface-on-the-canvas-skins-reveal-and-cursor.md) | A scene's widgets can live on the canvas (`UiSpace.Canvas`), a button or a panel is drawn by a skin (`ControlSkin`), text reveals itself by whole characters (`TextReveal`, `Label.Reveal`) and a self-drawn list has a cursor (`MenuCursor`): behaviour without a look returns to the UI, designed components stay examples (amends 0050) | Accepted |

Each number is used once. The numbers missing from the table:

- **0035 and 0036** are reserved for two decisions of the [ARCH-1 plan](../evaluations/arch-1.md) (section 7: validation
  by contract; assemblies by boundary with an architecture test). Each is written in the stage that records it; until
  then the plan holds the decision. ADR 0037 was numbered after this reserved range.
- **0039 and 0040** are not used: no record was merged under them, and the numbers stay empty rather than renumbering
  the records after them.
